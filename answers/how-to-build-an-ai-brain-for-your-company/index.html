How do I build an AI brain for my company without exposing client files?

An AI brain for a company is one private system that answers questions from the firm's own documents. Build it on five rules: follow the permissions you already have, keep sensitive files out, require a source for every answer, keep one approved copy of each team-built helper, and cap the cost of every run. Start with one team and one shared folder.

What is an AI brain for a company?

It is a system that reads your firm's own files (shared drives, email, call notes, past proposals) and answers questions in plain English. A person asks, "What did we tell this client last year?" and gets an answer with the file and page it came from.

It differs from pasting documents into a public chat window in two ways. The documents stay in an environment you control. And the system knows who is asking.

Which firms need one?

Any firm whose client or deal files can't go into a public chat tool, which covers most of private equity, law, life sciences and advisory. Their knowledge sits in shared drives, inboxes and a few senior people's heads, and those people have the least time to answer questions.

What are the five rules?

  1. Use the permissions you already have. Access should follow the folder rights you already set in SharePoint, Google Drive or wherever your files live. If someone can't open a file today, the AI should not quote it to them. A second permission system is how leaks happen, because nobody maintains it.
  2. Keep sensitive files out entirely. Some documents should never reach the model: fund documents, investor records, tax files. Exclude them by folder or label where documents are loaded. Asking the model to be careful with them is not a control.
  3. Require a source for every answer. Each answer points to the file and page it came from. An answer with no source gets rejected, not shown with a disclaimer. A partner can check any answer in ten seconds.
  4. Keep one approved copy of each team-built helper. Where people have built their own prompts and AI helpers, put one approved version of each in a shared library with a named owner. Otherwise you end up with six versions of the same helper and no way to know which one is current.
  5. Put a cost cap on every run. A loop that misreads a folder can run up a large bill before anyone notices. Use plain code for the steps that don't need a model, and the bill stays small after launch.

How do I start?

Pick one team and one shared drive. Write ten questions that team really asks, for example: "What did we tell this client last year?", "Which deals did we pass on, and why?", or a new hire's first-week questions. Load only that folder. Check every answer against its file.

A common first problem is the files, not the AI. Old versions sit next to new ones, and the system quotes the old one. Fix the files and the permissions, then widen the scope.

What does it not do?

It doesn't make decisions, and it won't fix messy file names. It's only as good as the documents it can read, and it says so when it can't find a source.
